# MotionBricks Blender アドオン 設計書

日付：2026-11-11
状態：利用者承認待ち

## 1. 目的と背景

利用者はゲーム用のキャラクターアニメーションを作りたい。動画からの抽出（Motion2MixamoRig＋補正）を実データで試したところ、仕上がりがゲームで使える水準にならなかった。そこで、ポーズを置いてその間を AI に埋めさせる NVIDIA MotionBricks を、Blender の中だけで使えるようにする。

利用者が思い描く流れ（利用者の言葉から）：

1. Blender を開き、N キーでパネルを出す。
2. 一番上の「MotionBricksを起動」を押すと MotionBricks が使える状態になる。
3. Blender の中で最初・途中・最後のポーズを置いて動きを生成する。
4. 満足したら「Mixamo形式で保存」を押してモーションを保存する。

MotionBricks を Blender 内で表示できない場合は別ウィンドウ起動でも可とされたが、できる限り Blender 内で完結させる（本設計は Blender 内で完結する）。

## 2. ゴール

- 最初・途中（0 個以上、並べ替え可）・最後のポーズを、ボタン中心の操作で簡単に置き換えられる。
- 各ポーズは「ポーズ集から選ぶ」と「自分で 1 から作る」の両方ができる。ポーズ集から選んだ後でも、手足（手首・足首など）の位置を自分で動かせる。
- MotionBricks で最初から最後までをつなぐ動きを生成し、Blender 内ですぐ再生して確認できる。
- 結果を Mixamo 形式で FBX に書き出せる。書き出し形式は 2 種類から選べる。
  - **キャラに焼き込み**：利用者の Mixamo キャラクター（メッシュ付き）に動きを焼き込んだ FBX。
  - **動きのみ**：Mixamo 骨格だけ（メッシュなし）の FBX。
- In Place（腰の水平移動を消す）を選べる。
- UI はすべて日本語。説明文は置かず、一目で分かる。ユーザーの操作はボタン中心。
- 自動化を最大限行う。インストール・起動・接続・骨格の準備・変換はすべて自動で、ユーザーはターミナルを触らない。

## 3. ゴールではないもの

- MotionBricks の Scene Preview（リアルタイム操作）、Smart Primitive、シーン編集の再現。
- Unitree G1（ロボット）モデルへの対応。人間（SOMA）モデルのみ。
- 動画からのモーション抽出。
- 他人への配布用パッケージ化（まずは利用者の PC で動けばよい）。

## 4. やってはいけないこと（技術的に動いても失敗とみなす）

- **MotionBricks 同梱のサンプル動き（`assets/motions/` の BVH/CSV）をポーズの元として使うこと。** これらは NVIDIA Sample Data Evaluation License で、評価・テスト目的の社内利用に限られ、派生物の配布も禁止されている。ポーズ集から選んだ姿勢で作ったアニメーションはゲームに入れる前提なので、サンプル動きはアドオンから一切参照しない（読み込み・一覧表示・初期値のいずれにも使わない）。利用者確認済み。
- ユーザーにコマンド入力、パス設定、仮想環境の操作、モデル選択などを求めること。
- 英語の UI ラベル、長い説明文、多数の詳細設定項目でパネルが混み合うこと。
- 生成や書き出しで、利用者のキャラクターや既存のアクションを上書き・破壊すること。

## 5. 前提と制約

- 環境：Windows 11、Blender 5.0（Python 3.11）、NVIDIA RTX 5080（VRAM 16 GB、ドライバ 617.42）。
- MotionBricks（https://github.com/NVlabs/motionbricks）は Python 3.12・uv・Git LFS・TensorRT（tensorrt-cu12 10.8）を必要とし、CUDA GPU 上でのみ動く。Blender 内蔵 Python では動かない。
- MotionBricks の SOMA モデルは 30 fps、1 回の生成で入力 4 ポーズ（context）＋目標 1〜4 ポーズ（target）を受け取り、約 0.6〜1.9 秒（18〜58 フレーム）の動きを返す。長い動きは「前の生成で最後に再生した 4 ポーズ」を次の context にして連鎖させる（公式 Inbetweener と同じ方式）。モデル自身が遷移の長さを決める。
- SOMA モデルの関節は 30 個（Hips, Spine1, Spine2, Chest, Neck1, Neck2, Head, Jaw, 両目, 両肩・腕・前腕・手, 両手の親指・中指の先端, 両脚の LeftLeg（太もも）・LeftShin（すね）・Foot・ToeBase）。指の個別関節はない。
- 推論に使う ONNX モデルはリポジトリ内（`motionbricks/assets/onnx/soma/`、Git LFS）にあり、Hugging Face からの取得は不要。モデルのライセンスは NVIDIA Open Model Agreement（商用利用可）。
- 初回起動時に TensorRT プランの構築に数分かかる（`.trt-cache/` にキャッシュされ、以降は速い）。
- MotionBricks の座標系：SOMA モデル空間は Y 上、アプリのワールドは Z 上。公式の `model_to_runtime` で変換する。
- 既存資産：本リポジトリ（Kimodo Blender Bridge のフォーク）には、Kimodo SOMA 骨格 → Mixamo への転送（`motion_tools.py` の `RigTransfer`、対応表、基本姿勢の違い・ロール・体格差・寝た基本姿勢の補正を含む）、In Place（`apply_in_place`）、Mixamo 骨格の判定、足の接地補正がある。Mixamo 側の名前接頭辞（`mixamorig:` など）の判定も既にある。
- 利用者のキャラクター例：`player_mixamo_repaired.fbx`（`mixamorig:` 接頭辞、65 ボーン、メッシュ Body / HeadHair）。

## 6. 決まった設計（利用者が決めたもの）

### 6.1 パネル（Blender 標準部品で構成、タブ名「MotionBricks」）

承認されたモックアップの並び（上から）：

**起動前**
- 「▶ MotionBricksを起動」ボタン 1 つだけ。

**初回の起動中**
- 進み具合のバー（例：「モデルを準備中… 45%」）と「中止」ボタン。

**起動後**
- 見出し「MotionBricks」：状態表示「✔ 起動中」と「■ 停止」ボタン。
- 見出し「ポーズ」
  - ポーズ一覧：最初（緑）、途中 1, 2…（オレンジ）、最後（青）。色はアイコンで表す。
  - 一覧の横に ＋（途中を追加）、－（削除）、▲▼（並べ替え）。最初と最後は削除できず、並びも固定。
  - 「ポーズ集」：選んだポーズに使うポーズ集の項目（例：歩き）を選ぶドロップダウン。
  - 「タイミング」：その動きのどの瞬間を使うかを決めるスライダー。
  - 「✋ 手足を編集」「↺ 元に戻す」ボタン。
- 見出し「生成」
  - 「▶ 生成」ボタン（大）。
  - 「⏵ 再生」「⟳ もう一度」ボタン。
- 見出し「書き出し」
  - 「キャラに焼き込み」／「動きのみ」の切り替え。
  - 「キャラクター」：Mixamo キャラクター FBX の指定欄とフォルダボタン。
  - 「📌 In Place」の押し込み式ボタン。
  - 「💾 Mixamo形式で保存」ボタン（大）。

今の Kimodo パネルにある Connection、詳細設定、Delete Venv、モデル選択、シード、出力形式、Variations、History、Manual Import に相当するものは置かない。

### 6.2 3D ビュー

- 各ポーズは SOMA 骨格（人形）として床の上に並び、位置と向きをドラッグで変えられる。骨格の色は一覧と同じ（最初＝緑、途中＝オレンジ、最後＝青）。
- 手足は手首・足首などをつかんで動かすと肘・膝が追従する（IK）。
- 生成した動きは Blender 内ですぐ再生して確認できる。

### 6.3 ポーズ集

- MotionBricks のサンプル動きは使わない（4 章）。代わりに **Kimodo で生成した動き** でポーズ集を作る。ポーズ集の項目は「動き（数秒のクリップ）」で、タイミングのスライダーでどの瞬間を使うかを選ぶ（公式 Inbetweener の「クリップ＋時刻」と同じ考え方。動いている瞬間を選べば勢いを持ったまま始まり、止まった瞬間を選べば静止から始まる）。

### 6.4 書き出し

- 形式は「キャラに焼き込み」（メッシュ付き FBX）と「動きのみ」（骨格のみ FBX）から選ぶ。
- In Place を選べる。

## 7. 実装者に任せる部分と、私（設計者）の判断

以下は利用者と合意したものではなく設計者の判断。実装者は理由があれば変えてよいが、変える場合は利用者に一言伝える。

1. **構成**：Blender アドオン（UI・3D 表示・変換・書き出し）と、MotionBricks の uv 環境で動く常駐サーバー（推論）の 2 プロセス構成。Kimodo Bridge と同じく、アドオンがサーバーを子プロセスとして起動し、ローカル通信（127.0.0.1 のみ）で JSON とポーズ配列をやり取りする。通信方式（TCP/HTTP、配列の受け渡し方法）は実装者に任せる。
2. **新しい独立したアドオン**として作る（Kimodo Bridge のフォークには入れない）。Mixamo 転送・In Place・Mixamo 判定などは本リポジトリのコードをコピーして使う。置き場所の初期案は `C:\Users\cielg\dev\motionbricks-blender`（新規 git リポジトリ、GitHub への公開は利用者の指示があるまでしない）。
3. **自動インストール（初回の「起動」で実行）**：
   - MotionBricks を特定のコミットに固定して取得（`%LOCALAPPDATA%` 配下など、利用者が意識しない場所）。
   - uv が無ければ公式の単体版を取得。Git LFS が無ければ取得または Git for Windows 同梱のものを使う。
   - `git lfs pull`、`uv sync`、初回の TensorRT プラン構築まで行い、進み具合をパネルのバーに出す。
   - 途中で失敗したら、次回の「起動」で続きから再試行できること。失敗理由は日本語の 1 行で表示する。
4. **ポーズ集の作り方**：アドオンの開発時に Kimodo（利用者の PC に既にある Kimodo 環境とモデル `Kimodo-SOMA-RP`）で動きを生成し、SOMA 形式のクリップとしてアドオンに同梱する。利用時に Kimodo は不要。初期の項目案：立ち（待機）、歩き、小走り、走り、しゃがみ、しゃがみ歩き、ジャンプ、座る、手を振る、振り返る。項目名は日本語。プロンプトとシードは記録しておく。
5. **自分で 1 から作るポーズ**：ポーズ集の先頭に「基本姿勢」を置き、そこから手足を編集して作る。静止ポーズとして扱う（context なら 4 ポーズとも同じ姿勢＝速度ゼロ）。
6. **手足の編集**：「手足を編集」で、選んだポーズの骨格に両手首・両足首の操作ハンドルと膝・肘の向きの目印（ポールターゲット）を付けたポーズモードに入る。腰・胸・頭は回転で動かせる。「元に戻す」はポーズ集から選んだ直後の姿勢に戻す。
7. **途中のポーズの扱い**：途中ポーズは目標として使い、1 つずつ順に生成を連鎖させる（公式 Inbetweener と同じ）。目標に使うポーズ数（1〜4）、手前で次へ切り替えるフレーム数などの細かな設定は自動で決め、パネルには出さない。初期値は公式 Inbetweener の既定に合わせる。最後のポーズは 1 ポーズ（そこで止まる）を既定とする。
8. **生成結果の表示**：書き出し欄でキャラクター FBX が指定されていれば、生成後すぐにそのキャラクターへ転送して再生する（未指定なら SOMA 骨格で再生）。キャラクターは非破壊で読み込み、元の FBX ファイルは変更しない。
9. **「動きのみ」書き出しの骨格**：指定されたキャラクター FBX の骨格（メッシュを除く）を使う。キャラクター未指定で「動きのみ」を選んだ場合は保存ボタンを押せない状態にし、欄を強調する。
10. **書き出し先**：保存ボタンで Blender 標準のファイル保存ダイアログを開き、ファイル名の初期値は自動で付ける。FBX の設定（30 fps、ボーンの向き、アニメーションのみの焼き込み等）は Mixamo FBX をそのまま Unity / Unreal に読み込める設定に固定し、パネルには出さない。
11. **足の補正**：MotionBricks は足の接地の確信度を返す。これを使った足滑り補正を Mixamo 転送後に自動でかけるかどうかは、実装者が生成結果を見て判断する（かける場合もパネルには出さない）。
12. **「もう一度」**：同じポーズで生成し直す。MotionBricks は決定的な生成なので、結果を変えるために遷移の長さの候補など内部の値をずらす。方法は実装者に任せる。
13. **床の上の位置の扱い**：置いた位置と向きは、そのまま MotionBricks の目標の位置・向きとして使う（モデルは目標に到達するよう学習されている）。1 回の生成（最長約 1.9 秒）で届かないほど離れた場合は、アドオンが自動で中間の目標を足して連鎖させる。この自動で足した目標は一覧に出さない。完成の条件 2 の「全ポーズを順に通る」は、各ポーズの位置・向き・姿勢に到達すること（目安：腰の位置の差 10 cm 以内）を意味する。
14. **ポーズ集のライセンス**：Kimodo の SOMA モデル（Kimodo-SOMA-RP）は NVIDIA Open Model License で、README では商用利用しやすいモーションキャプチャーデータ（Bones Rigplay 1）で学習したとされている。このライセンスでは NVIDIA は生成物の権利を主張しない。このため、Kimodo の生成物でポーズ集を作ることは利用者の目的（ゲームでの商用利用）と矛盾しないと判断した（法的な助言ではない）。実装時に、使うモデルの Hugging Face ページのライセンスがこの判断と変わっていないことを確かめ、変わっていたら作業を止めて利用者に伝える。
15. **RTX 5080 で TensorRT 10.8 が動かない場合**：MotionBricks の環境に限り、TensorRT・CUDA 関連の依存関係を新しい版へ上げてよい（固定したコミットへの最小限の差し替えとして記録する）。TensorRT 以外の GPU 実行（onnxruntime-gpu など）への切り替えや CPU 実行は、利用者に相談してから行う。
16. **骨格変換の経路**：MotionBricks の 30 関節の出力は、Kimodo の 77 関節 SOMA 骨格（指は基本姿勢）に載せ替えてから、既存の `RigTransfer` で Mixamo へ転送してよい。精度の目安は、SOMA→Mixamo の往復で関節位置の誤差 1 cm 以内。満たせない場合は原因を調べて直し、それでも直らなければ利用者に報告する。
17. **細かな既定**：指は Mixamo 側の基本姿勢（軽く開いた手）のままにする。書き出す動きは、最初のポーズの腰が原点に来るように平行移動する。ポーズの配置と生成結果は .blend ファイルに保存され、開き直しても続きから作業できる。
18. **既存ツールの利用**：この PC には Git 2.54、Git LFS 3.7.1、uv が既に入っている。自動インストールはまずこれらを使い、無い PC 向けの取得処理は後回しでよい。

## 8. 確認が必要な技術的リスク（実装の最初に確かめる）

- **SOMA 骨格の一致**：MotionBricks の SOMA（30 関節、`motionbricks/assets/human/soma_base_skel_minimal_no_root.usd`）と、Kimodo の SOMA（77 関節、`somaskel77`）は関節名が一致するが、骨の長さ・基本姿勢・軸の向きが一致するかは未確認。一致しなければ、Kimodo のポーズ集を MotionBricks の骨格へ変換する処理が必要。既存の `RigTransfer` 方式（関節ごとの基準姿勢の差を測って補正）で変換できる見込み。
- **TensorRT 10.8 と RTX 5080（Blackwell）**：公式の動作確認は RTX 4090。5080 でプラン構築と推論が動くかを最初に確かめる。動かない場合は利用者に報告する（勝手に CPU 実行などに切り替えない）。
- **Mixamo への転送の流用**：既存の `RigTransfer` は Kimodo の SOMA 骨格（BVH 由来）を前提にしている。MotionBricks の出力（30 関節）でも同じ精度が出るかを、往復誤差・関節位置誤差で確かめる。

## 9. 完成の条件

1. 新しい Blender（アドオンだけ入れた状態）で「MotionBricksを起動」を押すだけで、インストールから起動完了まで進む。ターミナル操作は一度も要らない。2 回目以降の起動は 1 分以内に終わる。
2. 最初・途中 2 つ・最後のポーズをポーズ集から選び、配置し、少なくとも 1 つは手足を編集した状態で「生成」を押すと、全ポーズを順に通る動きが Blender で再生される。
3. 「基本姿勢」から手足を編集しただけのポーズでも生成できる。
4. `player_mixamo_repaired.fbx` を指定して「キャラに焼き込み」「動きのみ」の両方で書き出せ、書き出した FBX を新しい Blender に読み込むと `mixamorig:` ボーンで同じ動きが再生される。In Place のオン・オフが反映される。
5. 生成・書き出しの前後で、利用者のキャラクター FBX と既存アクションが変わっていない。
6. MotionBricks のサンプル動きファイルを、アドオンが一度も読み込んでいない（コードとログで確認できる）。
7. パネルのラベルはすべて日本語で、6.1 の並びと一致する。
8. 目視で、膝の逆曲がり・大きな足滑り・体の突き抜けがない（生成元の MotionBricks 自体の癖は除き、変換で新たに生じたものがない）。
